# Free-FreeCell

GitHub Pages で遊べる、日本語のフリーセルです。
HTML・CSS・JavaScript の静的サイトで、ゲームはブラウザー内だけで動作します。
Node.js 24 と開発用の esbuild 0.28.2・html-minifier-terser 7.2.0 で公開ファイルを生成します。ゲーム実行時の外部依存はありません。

## 最上位の方針

- **全配布物を 50KB（50,000 バイト、圧縮前）以下**に収めます。HTML・CSS・JavaScript・Service Worker・追加素材を合計し、開発文書や Git 履歴は含めません。
- ゲーム操作・配札・保存を端末内で完結させ、初回取得と更新に必要な通信だけに抑えます。
- 初回取得とキャッシュ完了後は、インターネットなしで再起動して遊べることを初回公開の必須条件にします。
- ローカルコピーは `localhost` の HTTP サーバーで起動でき、外部のライブラリ・API・Web フォントなどを取得しません。

詳細は [実装方針](docs/architecture.md)、開発時の遵守事項は [AGENTS.md](AGENTS.md) を参照してください。

## 現在の状態

配札、1 枚・連続したカードの移動、Undo／Redo、新しいゲーム、同じ配りのやり直し、手数・時間、勝利判定を実装しています。
クリック・タップ・キーボードと、マウス・タッチのドラッグ＆ドロップで操作でき、進行の保存・復元と、配布版のオフライン起動に対応しています。
「最初からやり直す」で同じ配りに戻せます。Ctrl-Z で戻す、Ctrl-Y でやり直す操作ができ、Mac では ⌘ も使えます。文字入力や IME 変換中、確認画面ではショートカットを処理しません。
ドラッグは 1 枚と連続した並びに対応し、移動規則はクリック操作と共通です。盤面外へのドロップや Escape で中止できます。
ダブルクリック／ダブルタップでは手前の 1 枚をホームセル優先で送り、送れない場札は空きフリーセルへ移動します。
「自動」は安全なカードをホームセルへ続けて送り、「自動で送る」をオンにすると最初の成功した移動以降、操作後にも実行します。新しいゲームやリセットの直後は、設定がオンでも盤面・手数・時間を初期状態に保ちます。自動移動は 1 枚ずつ約 0.1 秒で動き、「戻す」で取り消せます。
赤の両ホームが 3 まで揃った場合は、黒の相方が 2 以上なら黒を 5 まで送れます。詳しい安全条件は [ゲーム仕様](docs/game-spec.md#安全な自動移動) に記載しています。
クリア後は 4 枚のキングが独立したタイミングで水平回転し、クリアした瞬間には短い 3 音を鳴らします。クリック音とホームへ置く音も小さく生成します。音声ボタンは「♪ 音声オン」「× 音声オフ」で現在の状態を示し、押すと切り替わります。外部素材・音声ファイル・追加通信は使いません。
スマートフォンでは最長の列と画面高に合わせ、8 列と上段の全セルを 1 画面に収めます。低い横向き画面では盤面だけに画面高を使い、左右の余白からスクロールして上の操作ボタンへ戻れます。カードの白い外枠は字形の四辺に均等な余白を取り、列の中央に置きます。
カード全体の絵柄には、同梱の Noto Sans Symbols 2 のトランプ文字を使います。52 枚それぞれの枠・数字・絵札の図形を描画します。[フォントの出典・ライセンス・再生成](docs/fonts.md)を記録し、外部のフォント配信へは接続しません。
新版の準備ができると「今すぐ更新」が表示され、進行を引き継いでそのタブだけを更新できます。
フッターの `ver-yyyy-mm-dd` はビルド時にアプリの最終更新日を日本時間で埋め込み、閲覧日や文書だけの更新では変わりません。
GitHub Pages への公開と、Chromium での本番操作・オフライン再起動を確認済みです。確認環境と未検証範囲は [検証記録](docs/verification.md) に記載しています。
GitHub リポジトリは [teizu/free-freecell](https://github.com/teizu/free-freecell) です。初回 push は完了しています。
`origin` は SSH 設定のホスト別名を使った `git@teizu-github:teizu/free-freecell.git` です。
公開サイト: **[https://teizu.github.io/free-freecell/](https://teizu.github.io/free-freecell/)**

## ローカルで遊ぶ

Node.js 24 と Python 3 がある環境で、リポジトリ直下から次を実行します。初回や依存の変更後は、`npm ci` でロックファイルに沿ってビルド用パッケージを準備します。

```sh
npm ci
npm run build
python3 -m http.server 8000 --bind 127.0.0.1 --directory dist
```

ブラウザーで <http://127.0.0.1:8000/> を開きます。終了は `Ctrl+C` です。
`npm ci` で未取得のパッケージを準備する際はインターネット接続が必要です。準備後のビルドとゲームはネット接続なしで動作します。生成済みの `dist/` を別の端末にコピーして使う場合、Node.js とビルド用パッケージは不要です。
「オフラインでも遊べます」と表示された後は、サーバーを止めても同じ URL で再起動できます。
ただし、ブラウザーのキャッシュ削除や保存禁止設定がある場合は、サーバーから再取得が必要です。

Python は静的ファイルの配信にだけ使用します。アプリの処理はすべてブラウザー内で動きます。
ES Modules と Service Worker を使うため、`file://` での HTML 直接起動は対象外です。

## 開発と検証

開発用ソースをビルドせず確認する場合は、公開物と別のポートを使います。

```sh
python3 -m http.server 8001 --bind 127.0.0.1 --directory src
```

<http://127.0.0.1:8001/> では Service Worker を登録しません。編集内容を直接確認でき、サーバー起動中はネット接続なしで遊べます。
オフライン再起動と更新動作は `dist/` で確認してください。

```sh
npm ci
npm test
npm run build
npm run check:size
```

`npm run build` は JS・CSS の空白・コメント・構文と JS の内部識別子を縮めて内容ハッシュを付け、Service Worker の保存対象を生成します。HTML も解析器でコメント・インデントを削減します。語間の空白と `pre`・`textarea`・`script`・`style` 内の内容は保持します。
`dist/` 全体が 50,000 バイトを超えると失敗します。`src/` の説明コメントと読みやすい識別子を保ち、配布 JS の内部名だけを短縮します。export 名やプロパティ名は維持し、esbuild の `minifySyntax` で意味を保ったまま構文を縮めます。日本語は UTF-8 のまま出力します。
表示日付はアプリに関係する最新 Git コミットから生成します。`SOURCE_DATE_EPOCH` の指定時はその UNIX 秒を優先し、Git がない場合はソースの最新更新日時を使います。再現方法は [実装方針](docs/architecture.md#表示する更新日) を参照してください。
esbuild と html-minifier-terser は開発依存として固定版を指定し、`package-lock.json` を管理します。依存の変更がなければ、毎回の `npm ci` は不要です。

## 構成

```text
src/
  index.html             盤面、操作ボタン、遊び方
  main.js                描画・操作・時計・各機能の接続
  drag.js                ドラッグの追従表示・移動先判定・中止
  effects.js             クリア演出・効果音・音声設定
  fonts/                 ライセンス情報を内包したトランプ文字・スートのフォント
  game.js                配札、合法手、自動移動、履歴、勝利判定
  storage.js             保存・復元と検証
  offline.js             オフラインの準備・更新状況
  sw.js                  配布版のキャッシュと更新
  styles.css             レスポンシブな盤面
scripts/                 ビルド・容量チェック・ブラウザー検証
tests/                   ゲーム・保存・ビルド・キャッシュのテスト
dist/                    生成された公開物（Git 管理対象外）
docs/
  README.md              文書の案内
  game-spec.md           ゲーム仕様・操作・受け入れ条件
  architecture.md        構成・実装・検証の方針
  deployment.md          GitHub Pages の公開手順
  roadmap.md             実装の順序と確認項目
  verification.md        検証結果と未確認の範囲
.github/workflows/
  pages.yml              main の検証と dist/ の公開
  check.yml              PR の検証
```

仕様は [docs/README.md](docs/README.md)、公開方法は [公開手順](docs/deployment.md) から確認できます。
`main` への push でテスト・ビルド・容量チェックを行い、成功した `dist/` を GitHub Pages に公開します。
開発文書だけの変更では再公開しません。
