# 実装方針

## 最上位の要件: 50KB と通信の最小化

全体サイズと通信量の制約を、追加機能や演出より優先します。
**配布物の合計を 50KB = 50,000 バイト以下**に収め、ゲームを端末内だけで進められる構成とします。
初回取得とキャッシュ完了後のオフライン再起動を、初回公開の必須条件にします。

サイズは HTTP 圧縮前の公開ファイルのバイト数を合計します。
HTML・CSS・JavaScript・Service Worker と、追加する画像・アイコン・manifest などをすべて含めます。
分割ファイルや遅延読み込みの追加機能も上限の対象であり、外部配信へ移して計測から外しません。
開発用ソース（生成物と別に管理する場合）、文書、テスト、Git 履歴、ブラウザーの保存データは含めません。
`npm run build` が `src/` から生成する `dist/` 全体を配布物として計測します。

HTTP ヘッダーや TLS の通信量はこのファイルサイズ上限に含めず、実際の転送量を公開環境で別途測定します。
初回取得時の重複ダウンロード、再訪時の再取得、更新確認・更新の通信量も確認対象です。
ビルド末尾と公開前の CI で容量を検証し、上限超過時は公開を止めます。

## 基本構成

HTML・CSS・JavaScript（ES Modules）で作る、ブラウザー内で完結する静的サイトとします。
利用者に見せるタイトルは `Free-FreeCell` とします。保存キーなどの内部識別子は維持し、既存の保存局を引き続き読み込めるようにします。
読みやすいソースを `src/` に集め、GitHub Pages には生成済みの `dist/` だけを公開します。
`docs/` は開発文書用であり、Pages の公開元には使用しません。

フレームワークは使いません。Node.js 24 のビルド処理で、内容ハッシュ付きのファイル名と Service Worker の保存対象を生成します。
容量上限を守るため、開発依存の esbuild 0.28.2 で公開用 JS・CSS の空白・コメント・構文を縮めます。`minifyWhitespace` と `minifySyntax` を有効にし、JS だけは `minifyIdentifiers` で内部名も短縮します。export 名とプロパティ名は維持します。`charset: 'utf8'` を指定し、日本語を UTF-8 のまま出力します。
HTML は開発依存の [html-minifier-terser 7.2.0](https://raw.githubusercontent.com/terser/html-minifier-terser/v7.2.0/README.md) で解析してコメント・インデントを削減し、参照 URL と更新日のプレースホルダーを書き換えます。`collapseWhitespace`・`conservativeCollapse`・`removeComments` だけを有効にし、語間の空白は 1 つ残します。`canTrimWhitespace` の判定で `pre`・`textarea`・`script`・`style` の内容と前後の改行を保護し、属性引用符や閉じタグは省きません。HTML 内の JS・CSS は追加で最小化しません。元の `src/` のコメントと整形は維持します。
両ツールの版を `package.json` に固定し、`package-lock.json` を管理します。初回や依存の変更後は `npm ci` で準備し、取得済みの依存があれば以降のビルドに通信は不要です。
実行時に外部のライブラリ・API・画像・Web フォントを取得せず、Wasm や大きなゲームエンジンは採用しません。
クライアントのルーティングも導入せず、1 ページで完結させます。

## ゲームの状態管理

ゲーム状態を唯一の正として保持し、DOM の並びからルールを判断しません。
ルール関数は現在状態と操作を受け取り、成功時は新しい状態を返す純粋関数を基本とします。
不正な移動では状態・履歴・手数を変更せず、失敗理由を UI で案内します。

カードには 0〜51 の一意な整数 ID を使い、そこからスートと数値ランク（1〜13）を求めます。
表示文字列からルールを判定せず、ゲーム中は常に 52 枚が重複・欠落なく存在することを守ります。
状態は通常の配列とオブジェクトで表現し、継承やイベント基盤の導入は避けます。

Undo／Redo は成功した手ごとの盤面スナップショットを使います。
52 枚の小さな状態なので、複雑な逆操作よりも再現性と読みやすさを優先します。
履歴の対象、手数、経過時間の扱いは [ゲーム仕様](game-spec.md) を正とします。
タイマーなど短周期の表示は個別に更新し、盤面再描画でキーボードフォーカスを失わせないようにします。
Ctrl／Meta-Z と Ctrl／Meta-Y はボタンと同じ履歴操作へ渡します。チェックボックス以外の入力欄・編集可能領域、IME 変換中、確認ダイアログ、Alt・Shift の同時押しを除外し、入力の編集を妨げません。「自動で送る」のチェック直後もショートカットを使えます。「最初からやり直す」は現在の初期配列へ戻す操作として、履歴の Redo と区別します。

ダブルクリック／ダブルタップは露出した 1 枚だけを扱い、合法なホームセルを優先します。
ホームへ送れない場札は最初の空きフリーセルへ送り、フリーセル内のカードを別のフリーセルへ移すことはしません。
この明示的な操作と、自動ボタン・チェックによる安全な自動移動の判定は分けます。
ドラッグ＆ドロップは Pointer Events でマウスとタッチを扱い、8 CSS px 以上の移動で開始します。
ドラッグ中の見た目だけを一時的に動かし、ドロップ先を座標から判定して既存の移動処理へ渡します。単札・連続札の合法性、手数、履歴、保存、自動移動はクリック操作と共有します。
盤面外・不正な場所へのドロップ、Escape、ポインター操作の中断では盤面を変えません。ドラッグ後のクリックが同じ移動を重ねて実行しないようにし、既存のクリック・ダブルクリック・キーボード操作を保ちます。

カードの `touch-action` は `pinch-zoom` とし、1 本指のドラッグと 2 本指の標準ピンチをブラウザーに振り分けてもらいます。2 本目の `pointerdown` と標準ジェスチャー開始時の `pointercancel` でドラッグを中止します。独自の拡大率・座標変換は持ちません。`visualViewport.scale` が 1 でない間は盤面の自動サイズ調整を止めます。仕様の根拠は [Pointer Events の touch-action](https://www.w3.org/TR/pointerevents3/#the-touch-action-css-property) と [pinch-zoom の定義](https://compat.spec.whatwg.org/#touch-action) です。

安全な自動移動は、ホームへ合法に置ける A・2、反対色の両スートが 1 段下まで揃った札、または反対色が両方 2 段下かつ同色の相方が 3 段下まで揃った札を対象とし、移動ごとに再判定します。後者では赤の両ホームが 3、黒の相方が 2 なら黒の 5 を送れます。同色の条件を省いて場札の足場を失わないようにします。判定の根拠と実行機会は [ゲーム仕様](game-spec.md#安全な自動移動) に記載します。
すべて通常の移動処理を通して 1 枚ずつ履歴へ追加するため、手数と Undo／Redo の規則を共有できます。
画面では `autoHome(game, 1)` で 1 枚だけ確定・描画・保存し、Web Animations API で元の位置からホームまで 100ms で動かしてから次へ進みます。入力・非表示・画面サイズ変更で演出と後続を中止し、確定済みの手を保ちます。実行番号を照合して古い非同期処理の再開を防ぎます。`prefers-reduced-motion: reduce` では全対象を即時処理します。
チェックがオンでも `game.started` が真になるまで自動移動しません。最初の成功した移動以降、成功した移動の後と、開始済みの局でチェックをオンにしたときに実行します。新規・リセット・未開始局の復元・未開始中のチェック変更は、盤面・手数 0・時間 0:00 を保ちます。明示的な「自動」ボタンでは開始前も実行でき、札を送れた時点で通常どおり開始します。Undo／Redo や保存局の復元直後は自動移動しません。

## クリア演出と音声

`effects.js` はゲーム状態と履歴を変更しません。クリア中のホーム 4 枚に、それぞれ独立したタイマーと Web Animations API の `rotateY(0deg)` → `rotateY(360deg)` を設定します。回転時間は毎回 100〜500ms、最初の待機と回転開始どうしの間隔は毎回 1〜15 秒から選び、別々の札の並行した回転を許容します。最短間隔が最長回転より長いため、同じ札の回転は重なりません。再描画・Undo・画面非表示では古いタイマーと回転を取り消し、`prefers-reduced-motion: reduce` では開始しません。

効果音は Web Audio API だけで生成し、音声ファイルは配布・取得しません。極小音量の方針は撤回し、クリア > ホーム移動 > フリーセル移動 > クリックの順に明確な強弱を付けます。クリック音は正弦波で 600Hz・25ms・最大 gain 0.02、フリーセル移動音は正弦波で 720Hz・60ms・最大 gain 0.08、ホーム移動音は正弦波で 900→1200Hz・90ms・最大 gain 0.2 にします。立ち上がりを 4ms にし、末尾をゼロへ戻してクリックノイズを避けます。最後のホーム移動では `move('foundations', true)` を呼び、三角波で 523・659・784・1047・784・1568Hz の 6 音を 120ms 間隔・最大 gain 0.5 で鳴らします。最初の 5 音は各 100ms、最後は 300ms、全体で 900ms です。最後に 1 オクターブ上がり、明るい音色と長めの余韻で完了を知らせます。専用音は成功した移動先を `move(zone, completed)` へ渡して鳴らし、クリック・キー・ドラッグ・二度押しで共用します。移動失敗・復元・再描画・Undo／Redo では専用音を鳴らしません。
同時に使う OscillatorNode は 1 つとし、クリアの 6 音もその周波数と gain へ予約します。信頼できる次の `pointerdown`・`keydown` の冒頭、新しい発音・ミュート・画面非表示で残音を止め、終了したノードを切り離します。履歴や対局を変える処理から新しいクリック音まで止めないよう、停止は入力時にまとめます。クリック音は document のバブリング段階で判定し、移動処理が既に音源を作っていたら鳴らしません。移動前のクリック音や移動音の上書きを避け、通常の操作音は維持します。AudioContext の作成と再開は信頼できるキー・ポインター入力時だけ行い、許可前の音は予約せず、非対応・許可待ちでもゲーム操作を続けます。音声設定は初期オンとし、ボタンには現在状態の「♪ 音声オン」「♪× 音声オフ」を表示して、`aria-pressed` を同期します。音符は CSS の疑似要素に置き、オフ時は赤い音符と × に切り替えます。最大化中は文字ラベルだけを隠して同じボタンを左下へ固定します。読み上げ名「音声」は維持し、左操作欄の下端を画面下から 56px 上に置き、スクロール中も音声ボタンと重ならないようにします。画像・外部フォント・複製ボタンは追加しません。

## 表示する更新日

フッターの `ver-__FREECELL_DATE__` はビルド時に `ver-yyyy-mm-dd` へ置き換えます。通常は `src/`・`scripts/build.mjs`・`package.json`・`package-lock.json` の最新 Git コミット時刻を日本時間の日付へ変換します。閲覧日時や文書だけのコミットでは進めず、同じソースの再ビルドでは同じ日付になります。CI は `fetch-depth: 0` で履歴を取得します。
`SOURCE_DATE_EPOCH` を指定した場合は、その非負整数の UNIX 秒を優先します。Git のないソース配布では `src/` 内のファイルの最新更新日時を使います。元の日付を保って再配布する場合はファイルの更新日時を保持するか、`SOURCE_DATE_EPOCH` を指定します。不正な日時では既存の配布物を書き換えずにビルドを失敗させます。`src/` 直接起動ではプレースホルダーのままなので、日付表示はビルド済みの `dist/` で確認します。

## 小画面での盤面配置

最大化は `body.maximized` と固定配置の `#board-scroll` を共通の表示にし、対応環境では実入力から `document.documentElement.requestFullscreen({ navigationUI: 'hide' })` を呼びます。アドレスバーを含むブラウザー UI の非表示を要求し、非対応・開始拒否時はページ内最大化を維持します。`fullscreenchange` で実際の状態を反映するため、戻る・Escape・ブラウザー側の終了操作でも通常表示へ復帰します。非同期の入退出中はボタンを無効にし、退出が拒否された場合は表示を維持して再試行可能にします。全画面の通知が重なっても元のスクロール位置を上書きしません。

`fullscreenchange` で全画面を確認してから `screen.orientation.lock('landscape')` を要求し、終了時は `unlock()` を呼びます。向き固定は全画面の入退出処理から分け、未対応・拒否・待機中でも解除を使えます。結果通知で表示状態を書き戻さず、実際の回転による resize で盤面を再計算します。[Screen Orientation API](https://developer.mozilla.org/en-US/docs/Web/API/ScreenOrientation/lock) と [全画面終了時の固定解除](https://w3c.github.io/screen-orientation/#fullscreen-interaction) に従います。

操作ボタンと時間・手数・ホーム枚数を `.controls` にまとめ、最大化中は幅 124px の左操作欄にします。`#board-scroll` は同じ CSS 変数の幅だけ左端を空けます。既存のボタン・数値表示とイベントを再利用するため、履歴・自動設定・時計・確認処理は通常画面と共通です。`.toolbar` と `.scoreboard` を縦に並べ、表示用のコピーや別のタイマーは持ちません。操作欄は縦スクロール可能にし、確認ダイアログも明示的に可視化します。

全画面中の標準ピンチはブラウザーによって制限されます。独自の拡縮は追加せず、通常表示へ戻せば標準ピンチを使えます。API と制約は [requestFullscreen](https://developer.mozilla.org/en-US/docs/Web/API/Element/requestFullscreen) と [モバイルでの拡縮制限](https://developer.mozilla.org/en-US/docs/Web/API/Fullscreen_API/Guide#viewport_scaling_in_mobile_browsers) を参照します。`#maximize` はカード再描画の外へ置き、VisualViewport の位置と倍率で右上へ追従させます。背後の要素は visibility で非表示にし、盤面・左操作欄・確認ダイアログだけを操作対象に保ちつつページ高を維持します。切り替え時にドラッグと後続の自動移動を止め、進行や履歴を変えず再計算します。解除時は元のスクロール位置へ戻します。

幅 800 CSS px 以下、または高さ 500 CSS px 以下では、8 列と上段の全セルを横スクロールなしで並べます。
CSS で間隔・見出し・操作ボタンを縮め、JavaScript で表示領域の高さ、盤面の開始位置、最長列からカード高と重なり幅を計算します。
横向きかつ高さ 500 CSS px 以下では、`.board-scroll` を `100dvh`（未対応時は `100vh`）にし、盤面だけで表示高を使います。ページ左右の 8px と盤面左右の 16px を合わせて各 24px の余白を残し、カードのドラッグと干渉せずメニューまで縦スクロールできます。初回またはこの表示条件に入った時だけ盤面上端へ移り、条件を外れた時はページ先頭へ移ります。通常の操作・再描画・同じ表示モード内のサイズ調整では位置を強制しません。
列が長い場合は字形と段差を一緒に縮め、上端のランクと小スートが見える段差を基本とします。カード幅は `(カード高 - 4px) × 574 / 766 + 4px` とし、輪郭の四辺に 2px の余白を残して列の中央へ置きます。幅の上限はボタンではなく列から読み、再計算ごとに縮み続けることを防ぎます。別のランク・スートを余白に足す補助表示は使いません。縦横の切り替えや画面サイズ変更、盤面更新で再計算します。
説明文、オフライン状態、ルールは盤面の下へ置き、下へのスクロールを許容します。極端に長い列や拡大表示では可読性に限界があるため、すべての条件で同じ文字サイズを保証しません。

## コメントと日本語

- シンプルな構造、美しい設計、可読性の順に優先します。
- ファイルと、1 行程度の自明な関数を除く関数には説明コメントを付けます。
- コメントには目的・前提・判断理由を書きます。特に複数枚移動の上限や履歴の扱いを説明します。
- すべてのテキストは UTF-8、改行は LF とし、HTML に `lang="ja"` と `charset="utf-8"` を指定します。
- 日本語文言とスート記号は Unicode の文字列として扱い、バイト単位の分割や切り詰めを行いません。
- 通常の文言挿入には `textContent` を使い、保存データを HTML として解釈しません。
- カード全体は Noto Sans Symbols 2 の 52 種類のトランプ文字で描画します。ランクとスートの記号を個別に組む方式ではなく、各文字に含まれる枠・数字・絵札の図形を使います。ホームセル用の 4 スートも含め、ライセンス情報を保持した WOFF2 を配布・キャッシュし、外部のフォント配信へ接続しません。操作文言とスコアは端末のフォントを使います。出典と再生成手順は [フォント管理](fonts.md) に記録します。

## 公開パスと保存

GitHub リポジトリは `teizu/free-freecell` とし、プロジェクトサイトの `/free-freecell/` を配信時のサブパスとします。
CSS、JavaScript、将来の画像、ページ内リンクは `./` などの相対パスにします。
ルートを指す `/styles.css` のような参照は使いません。

通常のゲーム状態は `localStorage` に保存し、アカウントやサーバー API は用意しません。クリック更新の再読み込み直前だけ、進行と自動設定を `sessionStorage` にも控えます。新版はこのタブ固有の控えを検証して一度だけ復元し、すぐ消費します。別タブによる `localStorage` の上書きが更新直前の盤面に影響しないようにします。
同一 GitHub Pages ホストには複数のサイトが置かれる可能性があるため、
保存キーにアプリ名・配置パス・保存バージョンを含めます（例: `freecell:/free-freecell/:v1`）。
「自動で送る」の設定は、このキーに `:auto-home` を付けて別途保存します。ゲーム状態の形式は変更せず、新しいゲームや Undo／Redo から設定を独立させます。設定がなければオフです。
音声設定も同じキーの `:sound` に独立して保存し、`0` はオフ、`1` はオンとします。設定がなければオンで、保存不可でも開いている画面の切り替えは使えます。
保存できないブラウザー設定でも、案内を表示して現在のゲームを続けられるようにします。
復元時は JSON の構造、スート、ランク、枚数・重複、ホームセルの順序、履歴の整合性を検証します。
不正な内容を一部だけ読み込まず、復元を見送って新しいゲームを開始し、理由を通知します。
複数タブの同期、統計、クラウド保存は初回の対象外です。

## オフラインと更新

配札・カード操作・履歴・ゲーム保存・時間表示はネットワークに依存させません。
新しいゲームもページの再読み込みを行わず、端末内で配札し直します。

初回のオンライン取得時に、Service Worker でゲームに必要なすべての公開ファイルをキャッシュします。
キャッシュ準備の完了を確認してからオフライン利用可能と案内します。
以後は保存済みのアプリを優先して使用し、ブラウザーを閉じた後でも、ネットワークなしで再起動・新規ゲーム・保存したゲームの続行を可能にします。
Service Worker とキャッシュの対象はこのアプリの配置パス内に限定し、同一オリジンにある別アプリのデータを削除しません。

通信は初回取得と更新確認・必要な更新ファイルの取得に限定します。
アプリ独自の定期ポーリングや操作ごとの更新確認は行いません。
起動に伴うブラウザー標準の Service Worker 更新確認を基本とし、確認に失敗してもゲームを開始・継続できます。
JS・CSS は内容が変わった場合だけ URL を変更し、同じ内容をキャッシュから再利用できるようにします。
同梱フォントも内容ハッシュ付き URL にし、未変更なら旧版のキャッシュから再利用します。WOFF2 は著作権・ライセンス情報を含むバイナリのままコピーします。ライセンス全文は外部の公式文書へリンクし、自動取得もオフライン保存もしません。OFL 原本は `docs/licenses/` に開発資料として保持します。条件の根拠は [フォント管理](fonts.md) を参照してください。
初回表示とキャッシュ準備で同じファイルを二重に取得していないかも実測します。

ビルドでは JS・CSS の参照先を先に変換し、空白・コメント・構文の短縮と JS の内部名短縮を行った内容からファイル名を決めます。
Service Worker はイベント登録だけを外部へ公開するため、ビルド時に IIFE へ閉じ込めて最上位の識別子も短縮します。ES Modules の構成と資産ごとのキャッシュは維持します。
Service Worker の URL は `sw.js` のままにし、内部に版と公開ファイルの SHA-256 一覧を埋め込みます。
インストール時は、まず変更のないファイルを既存キャッシュから探し、初回表示の HTTP キャッシュも再利用します。
全ファイルの内容が一覧と一致したときだけ準備完了とし、CDN の更新途中などで版が揃わない場合は新版を有効にしません。

新版のファイルがすべて揃ってから切り替え、異なる版の HTML と JS を混在させません。
通常は新版を待機させますが、準備完了時に「今すぐ更新」を表示します。クリック時に保存を確認し、待機 Worker への `APPLY_UPDATE` メッセージで `skipWaiting()` を実行します。適用完了後に最新の進行を再度保存し、押したタブだけを再読み込みします。保存失敗時は現在のゲームを残して再試行可能にします。`clients.claim()` は使いません。
別タブは自動再読み込みせず、同じボタンで個別に新版へ移れます。旧タブが残る適用では旧キャッシュを保持し、このアプリ配下の旧ハッシュ付きアセットだけを自アプリのキャッシュから返します。旧タブがない状態での次の有効化時に旧キャッシュを整理します。クリック更新を続ける間は複数版のキャッシュが端末に残る場合があります。これは端末の保存量であり、配布物の 50KB 集計とは区別します。
更新確認のポーリングは追加せず、準備済みの新版はオフラインでも適用できます。実装の基本パターンは [Chrome の更新ガイド](https://developer.chrome.com/docs/workbox/handling-service-worker-updates) に従い、外部ライブラリは追加しません。
キャッシュの更新を理由にゲームの保存データを消さず、保存形式の互換性は別に検証します。

ローカルコピーは `localhost` の HTTP サーバーから起動します。必要なファイルとサーバーが手元にあれば、インターネット接続は不要です。
`src/` の直接配信は編集確認用で、Service Worker を登録しません。オフライン再起動と更新処理は `dist/` で利用・検証します。
開発用と配布版のローカル確認には別ポートを使い、配布版のキャッシュがソース確認を妨げないようにします。
ES Modules と Service Worker を使うため、`file://` での HTML 直接起動は対象外です。
PWA のインストール画面や専用アイコンはオフライン動作の前提とせず、後から検討します。

未取得の端末やキャッシュが消去・退避された端末では、公開サイトのオフライン起動はできません。
ブラウザーが Service Worker や保存を禁止している場合もオフライン再起動を保証せず、その状態を案内します。
この場合でも、読み込み済みの画面でのプレイやローカル HTTP での利用は継続できる設計にします。

## 検証

JavaScript の構文、UTF-8、相対参照、HTTP 配信、文書間の整合性を確認します。
容量チェックと、キャッシュ完了後のオフライン再起動、ゲーム操作中の通信がないことを必須の検証にします。
`npm test` は Node.js 標準の `node:test` を使い、ルール・保存・ビルド・キャッシュの境界条件を自動検証します。
Node.js 24 を開発時の基準とし、ゲームの配信自体には Node.js を必要としません。
`package.json` は `type: module` と実行スクリプトを定義し、esbuild・html-minifier-terser を開発依存だけに持ちます。配布物にはビルド用パッケージや `node_modules/` を含めず、ブラウザー実行時には外部パッケージを取得しません。
CI は `npm ci` でロックファイルから依存を準備します。PR ではテストとビルド、`main` への push では同じ検証に続いて `dist/` の公開を行います。

初回公開前にはデスクトップとスマートフォンで操作・描画を確認します。
クリックとタップ、ドラッグ＆ドロップ、ダブルクリック／ダブルタップ、キーボード、安全な自動移動、保存失敗、破損データ、Undo／Redo 後の勝利状態を個別に検証します。
スマートフォンの縦向き・横向きで、初期盤面と長い列の全枠が画面内に収まること、横スクロールが発生しないことを確認します。
ブラウザーで未確認の条件を、構文チェックだけで動作確認済みとは扱いません。
具体的な確認条件は [実装計画](roadmap.md)、実行結果と未確認の環境は [検証記録](verification.md) に記載します。
