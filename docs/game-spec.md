# ゲーム仕様

この文書は、Free-FreeCell の現在の仕様を定める。以下のゲーム操作、保存・復元、配布版のオフライン起動を実装している。実際に検証した範囲と未確認の環境は [検証記録](verification.md) に分けて記載する。

## 最上位の要件

機能や演出を追加する際は、次の条件を最優先とする。

- 公開する全静的ファイルの合計を **50KB（50,000 バイト）以下**に抑える。上限は圧縮前の配布物に適用し、HTML・CSS・JavaScript・Service Worker と、採用する場合の画像・アイコン・マニフェストなどをすべて含む。開発文書、テスト、Git 履歴は含めない。
- 外部から取得するランタイム、画像、Web フォント、API に依存せず、ゲームに必要なものを配布物内に収める。
- 配札、カード操作、履歴、保存を端末内で完結させる。ゲーム操作に伴う通信を発生させず、バックグラウンドの定期通信も行わない。
- 初回取得とキャッシュ保存の完了後は、ブラウザーを閉じて再度開く場合も、ネット接続なしで新規ゲームと保存したゲームの続きを遊べるようにする。
- 配布物をローカルに置き、localhost の HTTP サーバーから開く場合も、インターネット接続なしで遊べるようにする。`file://` による HTML の直接起動は対象に含めない。

50KB はファイルサイズの基準であり、HTTP ヘッダーや更新確認を含む実際の通信量とは分けて測る。機能を追加するときは、この上限とオフライン動作を保つ。

## 目的と対象

- GitHub Pages 上で動作する、日本語のフリーセルを作る。
- ページのタイトルと画面の見出しは `Free-FreeCell` とする。
- インストールやログインをせず、ブラウザーで一局を遊べるようにする。
- パソコンのマウスとキーボード、スマートフォンのタッチ操作に対応する。
- サーバー、アカウント、ランキング、広告、課金は最初の公開版に含めない。

## 参考と採用方針

[Solitaire.Free の FreeCell](https://solitaire.free/freecell/) を、盤面と基本操作を検討する参考にした（確認日: 2026-11-03）。新しいゲーム、同じ配り直し、時間・手数表示、手を戻す・やり直す操作を最初の公開版に採用する方針とする。配色や文章、画像、ソースコードは独自に用意する。

安全なカードをホームセルへ送る自動移動も実装する。参考サイトにあるヒント、クリア可能な配りの選別などは今後の追加機能として扱う。参考サイトとの完全互換や、すべての配りがクリア可能であることは保証しない。

## 盤面と配り

| 領域 | 内容 |
| --- | --- |
| カード | ジョーカーを除く 52 枚。4 スートそれぞれ A〜K を 1 枚ずつ使う |
| 場札 | 8 列。すべて表向きで、左の 4 列に各 7 枚、右の 4 列に各 6 枚を配る |
| フリーセル | 4 枠。それぞれ任意のカード 1 枚を一時的に置ける |
| ホームセル（組札） | スペード、ハート、ダイヤ、クラブの 4 枠。対応スートの A〜K を順に積む |

場札は列の最下部を手前とし、手前にあるカードだけを動かせる。ハートとダイヤを赤、スペードとクラブを黒として扱う。A は 1、J は 11、Q は 12、K は 13 とする。

新しいゲームでは、重複のないデッキをシャッフルし、左から順に 1 枚ずつ 8 列へ繰り返し配る。初期配列を保持し、「最初からやり直す」で同じ配置に戻せるようにする。Microsoft 版のゲーム番号との互換性や番号共有は初期仕様に含めない。

## 移動規則

### 1 枚の移動

- 場札の手前のカード、またはフリーセルのカードを移動元にできる。
- カードがある場札には、その手前のカードと色が異なり、ランクが 1 小さいカードを置ける。例: 黒の 8 の上には赤の 7 を置ける。
- 空の場札列には、K に限らず任意のカードを置ける。
- 空のフリーセルには 1 枚だけ置ける。カードがあるフリーセルには置けない。
- ホームセルには、対応スートの A から始めて、手前のカードよりランクが 1 大きいカードを置ける。
- ホームセルからカードを戻す操作は採用しない。ただし、直前の移動は「戻す」で取り消せる。
- 移動元と移動先が同じ場合、または規則に合わない場合は盤面を変更しない。

### 連続したカードの移動

場札の途中のカードを選ぶと、そのカードから手前までの連続部分を移動対象とする。対象全体が色交互かつランク降順であり、移動先が場札である場合に限り、まとめて移動できる。ホームセルやフリーセルへは複数枚を直接移動できない。

まとめて移動できる枚数の上限は、移動前の盤面を使い、次の式で求める。

```text
上限枚数 = (空きフリーセル数 + 1) × 2 ^ 利用できる空き場札列数
```

「利用できる空き場札列数」には空の移動先を含めない。また、その移動で元の列が空になる場合も、元の列を空きとして数えない。対象の途中から一部だけを移すような自動補正は行わず、選択した全体を移せなければ移動を拒否する。

| 移動前の条件 | 上限 |
| --- | --- |
| 空きフリーセル 4、空き場札列 0 | 5 枚 |
| 空きフリーセル 4、空き場札列 1、カードがある列へ移動 | 10 枚 |
| 空きフリーセル 4、空き場札列 1、その空列へ移動 | 5 枚 |
| 空きフリーセル 0、利用できる空き場札列 0 | 1 枚 |

## 操作と表示

### カードの選択

クリックまたはタップで移動元を選び、続けて移動先を選ぶ。選択したカードと連続部分を明示し、同じ移動元をもう一度選ぶと選択を解除する。不正な移動では選択を維持し、理由を画面上の短いメッセージで知らせる。背景を押すか Escape キーを押すと選択を解除する。

キーボードでもカードと空き枠にフォーカスを移せるようにし、Enter または Space キーでクリックと同じ操作を行う。フォーカス位置は常に見えるようにする。Ctrl-Z で「戻す」、Ctrl-Y で「やり直す」を実行し、Mac の ⌘ でも同じ操作を行える。入力欄・編集可能領域、IME 変換中、確認ダイアログ表示中、Alt または Shift の同時押しでは、このショートカットを処理しない。ただし「自動で送る」のチェックボックスにフォーカスがある場合は、ゲームのショートカットを利用できる。

### ドラッグ＆ドロップ

マウスまたは指で場札・フリーセルのカードを押し、8 CSS px 以上動かすとドラッグを始める。それ未満の動きは通常のクリック・タップとして扱う。場札の途中からは、そのカードから手前までの並びを対象とし、ドラッグ中は対象のカードをポインターに追従させる。

カードまたは空き枠の上で離すと、その場所への移動を試みる。合法性と複数枚の上限はクリックによる移動と共通にし、成功したドロップを 1 手として履歴に残す。ホームセルのカードからはドラッグを開始しない。

盤面外や移動先のない場所へのドロップ、Escape、ブラウザーによるポインター操作の中断は移動を取り消す。不正な移動先でも盤面と履歴を変えず、理由を通知する。ドラッグ終了時のクリックを重複して処理せず、通常のクリック・タップ、ダブルクリック／ダブルタップ、キーボード操作を維持する。

カード上・空き枠・操作ボタン・背景のどこからでも、2 本指でブラウザー標準のピンチ拡大・縮小を行える。1 本指はカードのドラッグに使い、ドラッグ中に 2 本目の指を置いた場合は札を元の位置へ戻してピンチへ切り替える。指を離すまでドラッグを再開せず、盤面と履歴を変えない。拡大中はカードの自動縮小を止め、利用者が選んだ倍率を保つ。

### ダブルクリック／ダブルタップ

場札の手前の 1 枚、またはフリーセルのカードをダブルクリック／ダブルタップすると、合法ならホームセルへ送る。これは利用者がカードを指定した移動なので、次項の自動移動の安全条件は課さない。

ホームセルへ送れない場札は、左から最初の空きフリーセルへ送る。場札の途中、ホームセルのカード、空きフリーセルがない場合は移動しない。フリーセル内のカードは、ホームセルへ送れなければその場に残し、別のフリーセルへは移さない。

### 安全な自動移動

「自動」ボタンは、場札の手前とフリーセルにあるカードのうち、安全に送れるものをホームセルへ 1 枚ずつ移動する。移動後の盤面で再判定し、該当するカードがなくなるまで続ける。ホームセルへ合法に置けることに加え、次のいずれかを満たすカードだけを対象とする。

- ランクが A または 2。
- 反対色の両スートが、そのカードのランクより 1 小さいランクまでホームセルに揃っている。例: 赤の 5 は、スペードとクラブの両方が 4 以上まで揃っていれば対象とする。
- 反対色の両スートが 2 小さいランクまで、かつ同色の相方が 3 小さいランクまで揃っている。例: ハート・ダイヤが両方 3 以上、クラブが 2 以上なら、スペードを 5 まで自動で送れる。対象の札は露出し、そのスートの直前の札までホームに揃っている必要がある。

3 番目の条件で同色の相方を確認するのは、まだ残る小さい同色札を移すための足場を失わないためである。[KDE KPat の `good_automove` 判定](https://raw.githubusercontent.com/KDE/kpat/master/src/patsolve/freecellsolver.cpp)を参考に、反対色の条件だけで自動移動しない。

「自動で送る」チェックは初期状態でオフにする。オンでも最初の成功した移動までは実行せず、通常移動・ドラッグ＆ドロップ・ダブルクリック／ダブルタップで 1 手を進めた後から自動移動する。開始済みの局でチェックをオンにした直後にも実行する。「新しいゲーム」「最初からやり直す」、未開始局の復元、未開始中のチェック変更では、初期配列・手数 0・時間 0:00 を保つ。明示的な「自動」ボタンでは未開始でも対象札を送り、ゲームを開始できる。

不正な操作、選択だけの変更、「戻す」「やり直す」、および保存したゲームの復元の直後は実行しない。これにより、自動移動を取り消した盤面を確認・操作し、開き直した場合も保存時の盤面から再開できる。開始済みの局を Undo で最初の盤面まで戻しても、開始状態や経過時間は初期化しない。

自動移動は 1 枚ごとに 1 手として履歴へ追加する。各札を確定・保存した後、元の位置からホームセルまで約 100ms で動かしてから次の札へ進む。操作入力・画面の非表示・サイズ変更で後続を止め、確定済みの手だけを残す。「動きを減らす」設定ではアニメーションを省いて即時に移動する。「戻す」1 回で自動移動した 1 枚を戻せる。自動移動が始まれば通常の成功した移動と同じように時間計測を開始し、52 枚すべてが揃えば停止する。

### ゲーム操作

| 操作・表示 | 仕様 |
| --- | --- |
| 新しいゲーム | 別の配りを開始し、盤面・履歴・手数・時間を初期化する |
| 最初からやり直す | 現在のゲームの初期配列に戻し、履歴・手数・時間を初期化する |
| 戻す | 成功した移動を 1 回取り消す。履歴がなければ無効にする |
| やり直す | 取り消した移動を 1 回進める。戻した後に別の移動をしたら先の履歴を破棄する |
| 自動 | 安全に送れるカードがなくなるまでホームセルへ送り、1 枚ずつ履歴に残す |
| 自動で送る | 最初の成功した移動以降、安全な自動移動を操作後などにも行う。初期状態はオフで、設定を保存する |
| ♪ 音声オン／× 音声オフ | 現在の状態を示し、押すと切り替える。初期状態はオンで、`aria-pressed` にも状態を反映する |
| 手数 | 現在の履歴位置までの成功した移動数。複数枚の移動も 1 手とし、「戻す」で減り、「やり直す」で増える |
| 時間 | 最初の成功した移動で開始し、ページが表示されている間のプレイ時間を加算する。勝利中は停止する |
| 勝利 | ホームセルに 52 枚すべてが揃ったら完了を表示する |

進行中のゲームを「新しいゲーム」または「最初からやり直す」で置き換える際は、確認とキャンセルを用意する。「最初からやり直す」の確認は「初期状態にリセットしますか？」とし、ボタンは「リセットしない」「リセットする」とする。新しいゲームの確認は別の配りへ切り替える旨を表示する。未開始または勝利済みのゲームでは確認を省略する。新しいゲームで偶然同じ配りになる可能性は許容する。

不正な操作や選択だけでは手数を増やさない。「戻す」では時間を巻き戻さず、最初の手を取り消してもタイマーを初期化しない。勝利を取り消すとタイマーを再開し、再び勝利状態へ進めると停止する。バックグラウンドやブラウザーを閉じていた時間は加算しない。表示は分・秒とし、1 時間以上でも値を切り捨てない。スコア、連勝記録、手詰まり判定は初期仕様に含めない。

### クリア演出と効果音

クリア中は、ホームセルのキングを各スート独立に水平回転させる。各回転は `rotateY` の 1 回転で、所要時間を毎回 0.1〜0.5 秒から選ぶ。最初の待機と回転開始どうしの間隔は毎回 1〜15 秒から選び、4 枚が同時に回転することも許容する。画面非表示、動きを減らす設定、Undo などでクリア状態を離れた場合は、回転と待機を停止する。

操作時の短いクリック音と、カードをホームセルへ置いたときの少し長い音を小音量で鳴らす。最後の 1 枚をホームへ送ったときは、代わりに約 450ms の短い 3 音でクリアを知らせる。復元・再描画・Redo でクリア状態へ戻った場合は、クリア音を鳴らさない。

音は Web Audio API の正弦波から生成し、音声ファイルや追加通信を使わない。初期状態は音声オンだが、ブラウザーの再生許可は実際のキー・ポインター入力時だけ取得し、許可前の音は後からまとめて鳴らさない。同時に使う音源は 1 つに限り、次の利用者入力や発音、音声オフ、画面非表示で残りの音を停止する。Undo／Redo などの入力でも古い音を止め、その操作のクリック音は鳴らせる。音声非対応でもゲームを続けられる。

### 画面サイズとアクセシビリティー

- 小画面（幅 800px 以下または高さ 500px 以下）では盤面右上に「最大化」を表示する。ブラウザーの表示領域内で盤面を全面表示し、上部メニューなどは一時的に操作対象から外す。「解除」または Escape で元の位置へ戻す。縦横の回転でもモードと進行を維持し、ピンチ中も解除ボタンを可視領域に保つ。モードは保存せず、起動時は通常表示とする。
- 盤面を中心に、上部にゲーム操作と状態、下部に簡潔なルール説明を配置する。
- 文言は操作や状態を伝えるものに絞り、装飾的なキャッチコピーは使わない。フッターの著作権表示は `© 2026 teizu inc.` とする。
- フッターに `ver-yyyy-mm-dd` 形式のアプリ最終更新日を表示する。日付はビルド時に日本時間で確定し、閲覧日や文書だけの更新では変わらない。取得方法は [実装方針](architecture.md) に従う。
- 320 CSS px 幅から、8 列とフリーセル・ホームセルの各 4 枠を横スクロールなしで表示する。スマートフォンの縦向きでは、画面高と最長列に応じてカード高と重なり幅を縮小し、操作ボタン、状態、盤面全体を 1 画面に収める。
- 横向きかつ高さ 500 CSS px 以下では、盤面だけに表示高全体を使う。左右各 24px の余白からページを縦にスクロールし、上の操作ボタンや下の説明へ移動できる。初回の横向き表示・横向きへの切り替え時だけ盤面上端へ移り、縦向きへ戻るとページ先頭へ移る。その後のカード操作や再描画ではスクロール位置を強制しない。
- 画面の回転、サイズ変更、カード移動に応じて高さを再計算する。遊び方や保存・オフライン状態の説明は盤面の下へ置き、下へのスクロールを許容する。
- 非常に長い列、画面拡大、極端に低い画面では、すべてのカード名の可読性と 1 画面表示を同時に満たせない場合がある。カードを切り捨てず、必要なスクロールで手前のカードや選択対象に到達できるようにする。
- 赤・黒の色だけに依存せず、スート記号とランクを表示する。読み上げ用には「ハートの 7」のように日本語の名前を用いる。
- カード全体の絵柄には同梱の Noto Sans Symbols 2 のトランプ文字を使用する。52 枚の枠・数字・スート・絵札の図形を描き、ホームセル用の 4 スートとともにオフラインでも使う。操作文言やスコア表示は端末のフォントを使用する。
- 重なった札のランクと小スートが見える間隔を確保する。カードの横幅も字形の枠 574:766 と四辺 2px の余白に合わせて縮め、列の中央へ置く。ランク・スートを別の補助表示で重ねない。
- ゲームの状態変化と不正な移動理由は読み上げ可能な領域へ通知する。毎秒変わる時間は自動読み上げしない。
- `lang="ja"` と UTF-8 を明示し、日本語フォントが利用できない環境も考慮したフォント指定にする。
- 動きを減らす OS 設定を尊重し、ゲームの理解にアニメーションを必須としない。

## 保存と再開

現在の盤面、初期配列、戻す・やり直す履歴、手数、経過時間、開始状態を `localStorage` に保存し、同じブラウザーで再開できるようにする。成功した状態変更の後、ページが非表示になるとき、およびプレイ中の定期的な時点で保存する。保存間隔の目安は 10 秒とし、強制終了時には直近の保存以降の時間が失われる可能性を許容する。

保存データには形式のバージョンを持たせ、復元時に構造、カードの重複・欠落、領域ごとの枚数、ホームセルの連続性、履歴と現在位置の整合性を検証する。読めないデータや未対応のバージョンを盤面へ直接反映しない。復元できない場合は新しいゲームを開始し、理由を通知する。

保存領域の制限、容量超過、JSON の破損があっても、メモリー上ではゲームを続けられるようにする。保存できない状態は利用者に知らせる。保存内容はこのゲーム専用のキーに限定し、ほかのサイト機能のデータは削除しない。

復元後は保存した経過時間から再開し、ページを閉じていた時間は加算しない。同時に複数のタブで遊ぶ場合の統合は行わず、最後に保存したタブの内容を次回復元する。同一オリジンの別アプリと衝突しないよう、保存キーにはアプリ名・配置パス・保存形式のバージョンを含める。

「自動で送る」の設定はゲーム状態と別に保存し、ゲーム状態の保存キーに `:auto-home` を付けたキーを使う。設定は新しいゲームや「最初からやり直す」でも維持し、Undo／Redo では変更しない。保存した設定がオンでも、ゲーム復元時の盤面はそのまま維持し、次の成功した移動の後から安全な自動移動を行う。

音声設定は同じキーに `:sound` を付け、オフを `0`、オンを `1` として別に保存する。保存値がなければオンとし、新しいゲーム・リセット・Undo／Redo でも変更しない。保存できない場合も、開いている画面内では切り替えを維持する。

## オフライン起動と更新

Service Worker によるオフライン起動は MVP の必須機能とする。ゲームの状態保存は `localStorage`、起動に必要なファイルの保存は Service Worker のキャッシュで扱い、別の責務とする。オフライン起動には `npm run build` で生成した配布版を使う。開発用の `src/` を直接配信する場合は Service Worker を登録しない。

初回オンライン取得時に起動に必要なファイル一式を保存し、保存が完了したことを利用者が確認できるようにする。以後は保存済みのファイルを優先して使用する。オフラインでも配札、移動、新しいゲーム、最初からやり直す、戻す、やり直す、勝利判定、保存・復元、クリア演出と効果音を利用できるようにする。

更新確認の通信は起動時など必要な機会に限定し、定期的なポーリングを行わない。更新確認に失敗しても保存済みの版でゲームを開始できるようにする。新しい版の準備ができたら「今すぐ更新」を表示する。クリックすると進行・履歴・自動設定を保存し、そのタブだけを新版へ再読み込みする。保存できない場合は適用のための再読み込みを中止し、現在のゲームを続けられるようにする。別タブは強制再読み込みせず、各タブのボタンで更新できる。
再読み込み直前の控えをタブ固有の `sessionStorage` に保持し、復元時に検証して一度だけ取り込む。これは通常の複数タブ間のゲーム同期を提供するものではない。準備済みの更新はオフラインでも適用できる。ボタンを押さなければ、旧版を利用するタブがなくなるまで待機する。旧タブ用のアセットも保持し、各画面が読み込んだ版のまま動作できるようにする。

初回取得前、キャッシュ保存の失敗、利用者によるキャッシュ削除、ブラウザーによるキャッシュ破棄がある場合は、公開 URL からのオフライン起動は保証できない。再度オンラインで取得するか、ローカルの配布物を HTTP サーバーから開く。保存機能が禁止されている場合は、その制約を案内し、読み込み済みのゲームを続けられるようにする。

## 今後検討する機能

ヒントやソルバー、クリア可能性の保証、配り番号・URL 共有、統計、アカウント同期、多言語切り替え、テーマ選択、ホーム画面へのインストール UI やマニフェストは、基本の遊びやすさを確認してから検討する。これらを追加する場合も、50KB と最小限の通信量という上位要件を守る。ドラッグ操作、自動移動、オフライン起動、クリア演出と効果音は実装済みである。
