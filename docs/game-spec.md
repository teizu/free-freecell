# ゲーム仕様

この文書は、Free-FreeCell の現在の仕様を定める。以下のゲーム操作、保存・復元、配布版のオフライン起動を実装している。実際に検証した範囲と未確認の環境は [検証記録](verification.md) に分けて記載する。

## 最上位の要件

機能や演出を追加する際は、次の条件を最優先とする。

- 公開する全静的ファイルの合計を **50KB（50,000 バイト）以下**に抑える。上限は圧縮前の配布物に適用し、HTML・CSS・JavaScript・Service Worker と、採用する場合の画像・アイコン・マニフェストなどをすべて含む。開発文書、テスト、Git 履歴は含めない。
- 外部から取得するランタイム、画像、Web フォント、API に依存せず、ゲームに必要なものを配布物内に収める。
- 配札、カード操作、履歴、保存を端末内で完結させる。ゲーム操作に伴う通信を発生させず、バックグラウンドの定期通信も行わない。
- 初回取得とキャッシュ保存の完了後は、ブラウザーを閉じて再度開く場合も、ネット接続なしで新規ゲームと保存したゲームの続きを遊べるようにする。
- 配布物をローカルに置き、localhost の HTTP サーバーから開く場合も、インターネット接続なしで遊べるようにする。`file://` による HTML の直接起動は対象に含めない。

50KB はファイルサイズの基準であり、HTTP ヘッダーや更新確認を含む実際の通信量とは分けて測る。機能を追加するときは、この上限とオフライン動作を保つ。

## 目的と対象

- GitHub Pages 上で動作する、日本語のフリーセルを作る。
- ページのタイトルと画面の見出しは `Free-FreeCell` とする。
- インストールやログインをせず、ブラウザーで一局を遊べるようにする。
- パソコンのマウスとキーボード、スマートフォンのタッチ操作に対応する。
- サーバー、アカウント、ランキング、広告、課金は最初の公開版に含めない。

## 参考と採用方針

[Solitaire.Free の FreeCell](https://solitaire.free/freecell/) を、盤面と基本操作を検討する参考にした（確認日: 2026-11-03）。新しいゲーム、同じ配り直し、時間・手数表示、手を戻す・やり直す操作を最初の公開版に採用する方針とする。配色や文章、画像、ソースコードは独自に用意する。

安全なカードをホームセルへ送る自動移動も実装する。参考サイトにあるヒント、クリア可能な配りの選別などは今後の追加機能として扱う。参考サイトとの完全互換や、すべての配りがクリア可能であることは保証しない。

## 盤面と配り

| 領域 | 内容 |
| --- | --- |
| カード | ジョーカーを除く 52 枚。4 スートそれぞれ A〜K を 1 枚ずつ使う |
| 場札 | 8 列。すべて表向きで、左の 4 列に各 7 枚、右の 4 列に各 6 枚を配る |
| フリーセル | 4 枠。それぞれ任意のカード 1 枚を一時的に置ける |
| ホームセル（組札） | スペード、ハート、ダイヤ、クラブの 4 枠。対応スートの A〜K を順に積む |

場札は列の最下部を手前とし、手前にあるカードだけを動かせる。ハートとダイヤを赤、スペードとクラブを黒として扱う。A は 1、J は 11、Q は 12、K は 13 とする。

新しいゲームでは、重複のないデッキをシャッフルし、左から順に 1 枚ずつ 8 列へ繰り返し配る。初期配列を保持し、「最初から」で同じ配置に戻せるようにする。Microsoft 版のゲーム番号との互換性や番号共有は初期仕様に含めない。

## 移動規則

### 1 枚の移動

- 場札の手前のカード、またはフリーセルのカードを移動元にできる。
- カードがある場札には、その手前のカードと色が異なり、ランクが 1 小さいカードを置ける。例: 黒の 8 の上には赤の 7 を置ける。
- 空の場札列には、K に限らず任意のカードを置ける。
- 空のフリーセルには 1 枚だけ置ける。カードがあるフリーセルには置けない。
- ホームセルには、対応スートの A から始めて、手前のカードよりランクが 1 大きいカードを置ける。
- ホームセルからカードを戻す操作は採用しない。ただし、直前の移動は「戻す」で取り消せる。
- 移動元と移動先が同じ場合、または規則に合わない場合は盤面を変更しない。

### 連続したカードの移動

場札の途中のカードを選ぶと、そのカードから手前までの連続部分を移動対象とする。対象全体が色交互かつランク降順であり、移動先が場札である場合に限り、まとめて移動できる。ホームセルやフリーセルへは複数枚を直接移動できない。

まとめて移動できる枚数の上限は、移動前の盤面を使い、次の式で求める。

```text
上限枚数 = (空きフリーセル数 + 1) × 2 ^ 利用できる空き場札列数
```

「利用できる空き場札列数」には空の移動先を含めない。また、その移動で元の列が空になる場合も、元の列を空きとして数えない。対象の途中から一部だけを移すような自動補正は行わず、選択した全体を移せなければ移動を拒否する。

| 移動前の条件 | 上限 |
| --- | --- |
| 空きフリーセル 4、空き場札列 0 | 5 枚 |
| 空きフリーセル 4、空き場札列 1、カードがある列へ移動 | 10 枚 |
| 空きフリーセル 4、空き場札列 1、その空列へ移動 | 5 枚 |
| 空きフリーセル 0、利用できる空き場札列 0 | 1 枚 |

## 操作と表示

### カードの選択

クリックまたはタップで移動元を選び、続けて移動先を選ぶ。選択したカードと連続部分を明示し、同じ移動元をもう一度選ぶと選択を解除する。不正な移動では選択を維持し、理由を画面上の短いメッセージで知らせる。背景を押すか Escape キーを押すと選択を解除する。

キーボードでもカードと空き枠にフォーカスを移せるようにし、Enter または Space キーでクリックと同じ操作を行う。フォーカス位置は常に見えるようにする。ドラッグ操作と独自のショートカットは採用しない。

### ダブルクリック／ダブルタップ

場札の手前の 1 枚、またはフリーセルのカードをダブルクリック／ダブルタップすると、合法ならホームセルへ送る。これは利用者がカードを指定した移動なので、次項の自動移動の安全条件は課さない。

ホームセルへ送れない場札は、左から最初の空きフリーセルへ送る。場札の途中、ホームセルのカード、空きフリーセルがない場合は移動しない。フリーセル内のカードは、ホームセルへ送れなければその場に残し、別のフリーセルへは移さない。

### 安全な自動移動

「自動」ボタンは、場札の手前とフリーセルにあるカードのうち、安全に送れるものをホームセルへ 1 枚ずつ移動する。移動後の盤面で再判定し、該当するカードがなくなるまで続ける。ホームセルへ合法に置けることに加え、次のいずれかを満たすカードだけを対象とする。

- ランクが A または 2。
- 反対色の両スートが、そのカードのランクより 1 小さいランクまでホームセルに揃っている。例: 赤の 5 は、スペードとクラブの両方が 4 以上まで揃っていれば対象とする。

「自動で送る」チェックは初期状態でオフにする。オンにした直後、成功した通常移動とダブルクリック／ダブルタップ移動の後、および「新しいゲーム」「最初から」の開始時に、同じ安全な自動移動を行う。不正な操作、選択だけの変更、「戻す」「やり直す」、および保存したゲームの復元の直後は実行しない。これにより、自動移動を取り消した盤面を確認・操作し、開き直した場合も保存時の盤面から再開できる。

自動移動は 1 枚ごとに 1 手として履歴へ追加する。「戻す」1 回で自動移動した 1 枚を戻せる。自動移動が始まれば通常の成功した移動と同じように時間計測を開始し、52 枚すべてが揃えば停止する。

### ゲーム操作

| 操作・表示 | 仕様 |
| --- | --- |
| 新しいゲーム | 別の配りを開始し、盤面・履歴・手数・時間を初期化する |
| 最初から | 現在のゲームの初期配列に戻し、履歴・手数・時間を初期化する |
| 戻す | 成功した移動を 1 回取り消す。履歴がなければ無効にする |
| やり直す | 取り消した移動を 1 回進める。戻した後に別の移動をしたら先の履歴を破棄する |
| 自動 | 安全に送れるカードがなくなるまでホームセルへ送り、1 枚ずつ履歴に残す |
| 自動で送る | 安全な自動移動を操作後などにも行う。初期状態はオフで、設定を保存する |
| 手数 | 現在の履歴位置までの成功した移動数。複数枚の移動も 1 手とし、「戻す」で減り、「やり直す」で増える |
| 時間 | 最初の成功した移動で開始し、ページが表示されている間のプレイ時間を加算する。勝利中は停止する |
| 勝利 | ホームセルに 52 枚すべてが揃ったら完了を表示する |

進行中のゲームを「新しいゲーム」または「最初から」で置き換える際は、確認とキャンセルを用意する。未開始または勝利済みのゲームでは確認を省略する。新しいゲームで偶然同じ配りになる可能性は許容する。

不正な操作や選択だけでは手数を増やさない。「戻す」では時間を巻き戻さず、最初の手を取り消してもタイマーを初期化しない。勝利を取り消すとタイマーを再開し、再び勝利状態へ進めると停止する。バックグラウンドやブラウザーを閉じていた時間は加算しない。表示は分・秒とし、1 時間以上でも値を切り捨てない。スコア、連勝記録、手詰まり判定は初期仕様に含めない。

### 画面サイズとアクセシビリティー

- 盤面を中心に、上部にゲーム操作と状態、下部に簡潔なルール説明を配置する。
- 320 CSS px 幅から、8 列とフリーセル・ホームセルの各 4 枠を横スクロールなしで表示する。スマートフォンの縦向き・横向きでは、画面高と最長列に応じてカード高と重なり幅を縮小し、操作ボタン、状態、盤面全体を 1 画面に収める。
- 画面の回転、サイズ変更、カード移動に応じて高さを再計算する。遊び方や保存・オフライン状態の説明は盤面の下へ置き、下へのスクロールを許容する。
- 非常に長い列、画面拡大、極端に低い画面では、すべてのカード名の可読性と 1 画面表示を同時に満たせない場合がある。カードを切り捨てず、必要なスクロールで手前のカードや選択対象に到達できるようにする。
- 赤・黒の色だけに依存せず、スート記号とランクを表示する。読み上げ用には「ハートの 7」のように日本語の名前を用いる。
- ゲームの状態変化と不正な移動理由は読み上げ可能な領域へ通知する。毎秒変わる時間は自動読み上げしない。
- `lang="ja"` と UTF-8 を明示し、日本語フォントが利用できない環境も考慮したフォント指定にする。
- 動きを減らす OS 設定を尊重し、ゲームの理解にアニメーションを必須としない。

## 保存と再開

現在の盤面、初期配列、戻す・やり直す履歴、手数、経過時間、開始状態を `localStorage` に保存し、同じブラウザーで再開できるようにする。成功した状態変更の後、ページが非表示になるとき、およびプレイ中の定期的な時点で保存する。保存間隔の目安は 10 秒とし、強制終了時には直近の保存以降の時間が失われる可能性を許容する。

保存データには形式のバージョンを持たせ、復元時に構造、カードの重複・欠落、領域ごとの枚数、ホームセルの連続性、履歴と現在位置の整合性を検証する。読めないデータや未対応のバージョンを盤面へ直接反映しない。復元できない場合は新しいゲームを開始し、理由を通知する。

保存領域の制限、容量超過、JSON の破損があっても、メモリー上ではゲームを続けられるようにする。保存できない状態は利用者に知らせる。保存内容はこのゲーム専用のキーに限定し、ほかのサイト機能のデータは削除しない。

復元後は保存した経過時間から再開し、ページを閉じていた時間は加算しない。同時に複数のタブで遊ぶ場合の統合は行わず、最後に保存したタブの内容を次回復元する。同一オリジンの別アプリと衝突しないよう、保存キーにはアプリ名・配置パス・保存形式のバージョンを含める。

「自動で送る」の設定はゲーム状態と別に保存し、ゲーム状態の保存キーに `:auto-home` を付けたキーを使う。設定は新しいゲームや「最初から」でも維持し、Undo／Redo では変更しない。保存した設定がオンでも、ゲーム復元時の盤面はそのまま維持し、次の成功した移動の後から安全な自動移動を行う。

## オフライン起動と更新

Service Worker によるオフライン起動は MVP の必須機能とする。ゲームの状態保存は `localStorage`、起動に必要なファイルの保存は Service Worker のキャッシュで扱い、別の責務とする。オフライン起動には `npm run build` で生成した配布版を使う。開発用の `src/` を直接配信する場合は Service Worker を登録しない。

初回オンライン取得時に起動に必要なファイル一式を保存し、保存が完了したことを利用者が確認できるようにする。以後は保存済みのファイルを優先して使用する。オフラインでも配札、移動、新しいゲーム、最初から、戻す、やり直す、勝利判定、保存・復元を行えるようにする。

更新確認の通信は起動時など必要な機会に限定し、定期的なポーリングを行わない。更新確認に失敗しても保存済みの版でゲームを開始できるようにする。新しい版が見つかっても対局中に強制更新せず、次回起動時などゲームを妨げないタイミングで切り替える。旧版と新版のファイルを混在させない。

初回取得前、キャッシュ保存の失敗、利用者によるキャッシュ削除、ブラウザーによるキャッシュ破棄がある場合は、公開 URL からのオフライン起動は保証できない。再度オンラインで取得するか、ローカルの配布物を HTTP サーバーから開く。保存機能が禁止されている場合は、その制約を案内し、読み込み済みのゲームを続けられるようにする。

## 今後検討する機能

ヒントやソルバー、クリア可能性の保証、ドラッグ操作、配り番号・URL 共有、統計、アカウント同期、多言語切り替え、テーマ選択、音声、ホーム画面へのインストール UI やマニフェストは、基本の遊びやすさを確認してから検討する。これらを追加する場合も、50KB と最小限の通信量という上位要件を守る。自動移動とオフライン起動は実装済みである。
